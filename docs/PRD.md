## 1. 对标分析：2048 的"顶级"到底在哪

以 [gabrielecirulli/2048](https://github.com/gabrielecirulli/2048) 为质量标尺。它的成功**不来自功能多**，而来自极端的约束与极低的进入成本。逐条拆解并映射到本项目：

| 维度 | 2048 的做法 | 对我们的启示 | 我们的做法 |
|---|---|---|---|
| 定位 | README 第一句就是 "Made just for fun" | 不承诺商业价值，只承诺体验 | 同样不引入账号、商城、社交 |
| 学习成本 | 3 行说明 + 一个手势（方向键/滑动） | 不能有教程页 | 无教程；开局遮罩一句话说明玩法 |
| 机制数量 | 单一机制（合并同数），深度靠组合涌现 | 只做一个核心循环 | 单一机制（吃、长、撞死），深度靠节奏与风险取舍 |
| 分发 | GitHub Pages 静态托管，零服务器成本 | 静态优先 | GitHub Pages，纯前端，无后端 |
| 体积 | 无构建、直接可读的源码 | 首屏必须快 | **3 个请求 / 31.9 KB 原始 / 9.9 KB gzip** |
| 存档 | 最高分存 localStorage（由社区 PR 补上） | 轻量持久化即可 | 内置，且静音偏好一并持久化 |
| 移动端 | 滑动操作经社区多次修补（含 Windows Phone） | 移动端不是附属品 | 滑动 + 虚拟方向键，`pointer: coarse` 才显示 |
| 协议与协作 | MIT，欢迎 PR | 可被复用、可被改进 | MIT，逻辑层与渲染层分离以便他人改 |
| **明确不做** | 无账号、无排行榜、无内购 | 不做清单比做清单更重要 | 见 §3 非目标 |

**结论**：对标 2048 不是"抄它的功能"，而是抄它的**取舍纪律**——用更少的东西换更低的进入成本，把复杂度全部压在玩法本身。

## 2. 问题定义

> **在等待、通勤、会议间隙拥有 1–3 分钟碎片时间的手机与桌面用户**，想要**一个不用学、不用注册、随时能停、死也死得明白的即时娱乐**，
> 但现在**打开网页小游戏要等广告 SDK 与字体图片加载，弱网下直接打不开；手机上方向控制容易误触；贪吃蛇类游戏普遍存在"按了没反应"的输入丢失**，
> 导致**用户 5 秒内离开，且不具备重开意愿**。
>
> 证据：本项目实测首屏 3 请求 / 9.9 KB(gzip)，证明"轻"是可达成且必须守住的底线；输入丢失与误触为品类通病（见 §2.1 归因）。

### 2.1 证据与归因

| 类型 | 内容 | 可信度 |
|---|---|---|
| 实测 | 首屏仅 3 个请求（`index.html` / `game.js` / `app.js`），原始 31,860 B，gzip 10,156 B，压缩比 31.9% | 高（可复现，见附录 A） |
| 实测 | 静态图片资源可用性：`raw.githubusercontent.com` 连续 6 次仅 4 次成功（67%）；改走 jsDelivr 后 6/6 | 高 |
| 实测 | 逻辑层 19 项断言全部通过，含"尾部正在腾出格子时允许穿入"这一经典边界 | 高 |
| 品类观察 | 贪吃蛇类实现的常见缺陷：只记录最后一次方向 → 快速连打丢键；无插值 → 视觉跳格 | 中高 |
| `[假设]` | 碎片时间用户对首屏 > 2s 的容忍度显著低于对画面精致度的要求 | 中（需 A/B 验证首屏时间与跳出率的相关性） |
| `[假设]` | 单局 45–120s 是"再来一局"意愿最高的区间 | 中（需对局时长分布数据验证） |

> 标注 `[假设]` 的部分在附录 C 写明验证方式；未验证前不作为排期依据。

## 3. 目标与非目标

### 3.1 目标（结果导向，可验证）

| 编号 | 目标 | 判据 | 现状 |
|---|---|---|---|
| G1 | 首屏可交互 | 冷缓存下 < 1.0s（本地）/ < 2.0s（4G） | 9.9 KB(gzip) / 3 请求，本地实测远低于阈值 |
| G2 | 单局时长合理 | 中位数落在 45–120s | 待埋点验证（见 §6） |
| G3 | 有重开意愿 | 会话内重开次数中位数 ≥ 2 | 待埋点验证 |
| G4 | 移动端可用 | 竖屏单手可完成整局，无意向外的误触 | 滑动 + D-pad 已实现，待真机验证 |
| G5 | 零崩溃 | 纯前端无外部依赖，运行期异常为 0 | 19 项断言通过，无运行期报错 |
| G6 | 可被验证 | 核心逻辑可确定性测试 | 已达成（注入种子 + 19 断言） |

### 3.2 非目标（本次明确不做，附理由）

| 不做 | 理由 |
|---|---|
| 账号体系 / 云存档 | 引入后端与隐私成本，与本项目"零注册即刻玩"的核心价值冲突 |
| 全球排行榜 | 需要后端与反作弊；且排行榜会把"随便玩玩"变成"必须赢" |
| 关卡、剧情、Boss | 与单一机制原则冲突，会把 3 分钟体验拉成 30 分钟 |
| 皮肤 / 内购 / 广告 | 直接破坏首屏速度与体验纯度 |
| 多人对战 | 需要实时同步基础设施，远超本项目边界 |
| 音频资源文件 | 用 Web Audio 现场合成，避免额外请求与授权问题 |
| PWA / 离线安装 | 收益待评估（P2），当前 GitHub Pages 已满足"打开即玩" |
| 撤销一步 / 复活 | 会稀释"一次失误就是结束"的紧张感，需实验证伪后再议 |

## 4. 用户与场景

### 4.1 用户分层

| 层级 | 描述 | 设计影响 |
|---|---|---|
| 主要（Primary） | 手机端碎片时间用户：竖屏、单手、注意力易被打断 | 单手可操作、随时可暂停、单局可短 |
| 次要（Secondary） | 桌面端用户：办公间隙用键盘玩 | 方向键 / WASD、空格暂停、R 重开 |
| 负向（Negative） | 需要长期养成、关卡进度、社交比较的玩家 | 明确不为其设计，不因他们加功能 |

### 4.2 JTBD

- 当我**在等电梯/等编译/等地铁**时，我想**立刻玩点什么而不需要学习或注册**，以便**把这几分钟填满而不觉得浪费**。
- 当我**被打断（来电、消息）**时，我想**回来时局面还在**，以便**不用从头再来**。
- 当我**死掉**时，我想**清楚知道为什么死**（撞墙还是咬到自己），以便**下一局不重犯**。

### 4.3 关键旅程

**A. 冷启动（首次访问）**
`打开链接` → 直接看到棋盘与蛇（无加载动画）→ 底部一句话说明玩法与操作 → `按方向键或点击 Play` → 开始。
中断点：若首屏空白 > 1s，用户流失；若说明文案挡住棋盘，用户误以为页面坏了（**已修复，见 ADR-4**）。

**B. 正常一局**
`移动` → `吃苹果（+1，轻微闪光与音效）` → `每 5 个苹果出现金色碎片（+5，带倒计时环）` → `蛇身变长、速度提升` → `失误死亡`。
中断点：转向无响应（输入丢失）→ 用户认为是"游戏有问题"而非"我按错了"（**由两格输入缓冲解决**）。

**C. 死亡与重开**
`撞击` → 短暂震屏 + 粒子 + 死亡音效 → 显示得分与最高分（破纪录时显示 New best）→ `按 R 或点击重开`。
中断点：死亡原因不明（未区分撞墙/咬自己）→ 挫败感无法归因（**已在文案中区分**）。

## 5. 需求

### 5.1 优先级判级规则

| 级别 | 判级标准（只看对目标的贡献，不看实现难度） |
|---|---|
| **P0** | 缺失则 G1/G4/G5 任一不成立，或上线即不可玩 |
| **P1** | 显著影响 G2/G3/G4，但有可接受的降级方案 |
| **P2** | 体验优化，不影响目标达成 |

### 5.2 P0 需求

**P0-1 首屏即刻可玩**
```
作为 碎片时间用户
我想 打开即见棋盘，不用等加载
以便 这不是一次"等待"而是一次"开始"

验收标准：
- Given 冷缓存、4G 网络
  When 打开页面
  Then 棋盘与蛇在 1.0s 内可见且可响应输入
  And 首屏请求数 = 3（html + 2 个 js），无第三方脚本、无字体、无图片
```

**P0-2 三套等价输入**
```
验收标准：
- Given 桌面浏览器
  When 按 ↑↓←→ 或 WASD
  Then 蛇按对应方向转向，且页面不滚动
- Given 触摸设备
  When 在棋盘上滑动（位移 ≥ 24px）
  Then 按主轴方向转向
- Given 触摸设备且指针为 coarse
  Then 显示屏幕方向键，且点击可转向
```

**P0-3 输入不丢失、不自杀**（核心竞争力）
```
验收标准：
- Given 蛇向右移动
  When 快速依次按 上、左
  Then 两次转向都被执行（缓冲深度 2）
- Given 蛇向右移动
  When 按左（180° 反向）
  Then 该输入被忽略，蛇不死亡
- Given 缓冲已满
  When 继续按第四个方向
  Then 新输入被丢弃而非覆盖已排队的转向
```

**P0-4 死亡与重开**
```
验收标准：
- Given 蛇头撞墙
  Then 立即停止、触发震屏与粒子、显示"撞墙"原因
- Given 蛇头撞到自身
  Then 显示"咬到自己"原因
- Given 游戏结束界面
  When 按 R 或点击重开
  Then 立即开始新一局，分数归零，棋盘重置
```

**P0-5 最高分持久化**：`localStorage` 存最高分，跨会话保留；破纪录时给出明确提示。

**P0-6 暂停与自动暂停**：`Space` 切换暂停；页面隐藏（切标签/失焦）时自动暂停，避免"回来已经死了"。

**P0-7 竖屏单手可玩**：棋盘随视口自适应为正方形，`min(92vw, 68vh, 640px)`；控件不重叠。

### 5.3 P1 需求

| 编号 | 需求 | 说明 |
|---|---|---|
| P1-1 | 金色碎片 | 每 5 个苹果生成一次，+5 分，26 步后过期，带可视倒计时环 |
| P1-2 | 合成音效与静音持久化 | Web Audio 现场合成，首次手势后初始化，静音状态写入 localStorage |
| P1-3 | 帧插值 | 逻辑按格步进，渲染在前后两格间插值，消除跳格感 |
| P1-4 | 减少动态效果适配 | 系统 `prefers-reduced-motion` 时关闭震屏并削减粒子数量 |
| P1-5 | 高 DPI 适配 | 按 `devicePixelRatio` 渲染，上限 2 以避免移动端填充率过高 |

### 5.4 P2 需求（未排期）

主题皮肤、撤销一步、每日挑战、PWA 离线、排行榜。

### 5.5 非功能需求

| 维度 | 要求 | 现状 |
|---|---|---|
| 性能 | 稳定 60fps；单帧绘制不分配大量临时对象 | 达成（对象池式粒子 + 复用上下文状态） |
| 体积 | gzip 后 ≤ 15 KB | **10,156 B**，达标 |
| 容量 | localStorage 占用 ≤ 10 KB | 2 个键值对，约 60 B |
| 可用性 | 依赖项越少越好；实测静态资源可用性需 ≥ 95% | `raw.githubusercontent` 仅 67%，故图片改走 jsDelivr（100%） |
| 降级 | 无后端可降级；资源加载失败时页面不可用 | 单点依赖，已通过多 CDN 与体积最小化缓解 |
| 安全 | 无用户输入、无网络请求、无第三方脚本 | 达成（零 XSS 面、零数据外流） |
| 隐私 | 不收集任何数据，不使用 Cookie，不做指纹识别 | 达成（仅 localStorage 本地分数） |
| 可访问性 | 键盘全可达；`prefers-reduced-motion`；canvas 有 `aria-label`；对比度达标 | 达成（P1-4、aria 标注） |
| 国际化 | 文案英文，硬编码于 HTML | **未达标**：文案未外部化，列为 P2 |
| 可观测性 | 能定位崩溃 | **未达标**：无埋点无错误上报（见 §6.3 计划） |

## 6. 指标与埋点

### 6.1 指标树

```
北极星：会话内有效对局数（时长 ≥ 30s 的对局 / 会话）
   ↑
输入指标：① 首屏可交互时间  ② 首次输入延迟  ③ 会话内重开率
   ↑
护栏指标：① 帧率 < 50fps 的会话占比  ② 非预期转向率（误触）  ③ JS 运行时错误数
```

### 6.2 反指标

**难度下探**：把速度曲线调缓可以提升单局时长与重开率，但会牺牲"紧张感"。
→ 约束方式：同时监控**单局时长中位数**，若 > 180s 视为难度过低，需回调节奏曲线。

### 6.3 埋点设计（当前未接入，属已知缺口）

| 事件 | 触发 | 属性 | 用途 |
|---|---|---|---|
| `page_ready` | 首帧渲染完成 | `load_ms`, `dpr` | G1 |
| `game_start` | 进入 playing | `source: keyboard/swipe/dpad` | 输入偏好 |
| `game_over` | 死亡 | `score`, `duration_ms`, `cause: wall/self`, `length` | G2、归因 |
| `restart` | 重开 | `previous_score` | G3 |
| `turn_ignored` | 输入被拒 | `reason: reverse/duplicate/buffer_full` | 误触与手感诊断 |
| `fps_drop` | 连续 60 帧均值 < 50 | `avg_fps`, `dpr` | 护栏 |

> 由于本项目坚持"零第三方脚本"，埋点应走自建轻量端点而非第三方 SDK；接入前需先确认不破坏 §3.1 G1。

### 6.4 成功判据与失败退出

- **成功**：G1 达成，且 G2 中位数落在 45–120s，且护栏指标无恶化。
- **失败退出**：上线 2 周后重开率中位数 < 1.5，或误触率 > 10% → 回退到"无输入缓冲"版本做 A/B，而非继续加功能。

## 7. 方案与备选（含取舍）

### 7.1 渲染方案

| 维度 | DOM 元素 | **Canvas 2D（选定）** | WebGL |
|---|---|---|---|
| 24×24 = 576 格的每帧更新 | 触发 layout/paint，移动端易掉帧 | 单次 `drawImage` 级开销，可控 | 过度设计 |
| 渐变与辉光 | 依赖 CSS，逐段渐变成本高 | 原生支持 | 支持 |
| 复杂度 | 低 | 中 | 高 |
| 结论 | 掉帧风险不可接受 | **选定** | 不选，收益与成本不匹配 |

**决定性理由**：24×24 的格数在 DOM 方案下每帧都要改 576 个节点的样式，移动端必然掉帧；Canvas 2D 足够，WebGL 在这个规模没有收益。

### 7.2 输入模型

| 方案 | 表现 | 结论 |
|---|---|---|
| 只记最后一次方向 | 快速连打"上→左"会丢键，玩家认为游戏出 bug | 否 |
| 无缓冲（立即生效） | 一帧内多次转向导致自撞 | 否 |
| **队列深度 2 + 拒绝反向 + 拒绝重复** | 连打不丢、不自杀 | **选定** |

**决定性理由**：这是本产品唯一的"手感"来源。深度取 2 而非 3，是因为 3 会产生"我按了它却不立刻转"的延迟感。

### 7.3 运动表现

| 方案 | 观感 |
|---|---|
| 按格跳（渲染 = 逻辑坐标） | 卡顿、廉价 |
| **前后格插值（`renderCell(i, t)`）** | 丝滑，且在低帧率下仍平滑 |

**决定性理由**：插值是"看起来是否像一个完成品"的分水岭，实现成本仅一个 lerp。

### 7.4 棋盘尺寸

| 尺寸 | 单局时长 | 手机可点性 | 结论 |
|---|---|---|---|
| 4×4（2048 式） | 过短，一局 < 20s，缺乏成长感 | 极好 | 否 |
| 16×16 | 偏短 | 好 | 备选 |
| **24×24** | 45–120s 区间 | 每格约 28px，可接受 | **选定** |
| 32×32 | 长，易疲劳 | 每格 < 22px，误触上升 | 否 |

### 7.5 资源策略

| 方案 | 风险 |
|---|---|
| 第三方图床 | 实测 33% 失败率，裂图直接毁掉第一印象 |
| **无外部图片 + 截图走 jsDelivr** | 失败率 0/6 |

|---|---|---|---|---|---|
| P0-3 输入缓冲（不丢键不自杀） | 100% 玩家 | 3 | 90%（边界已断言） | 0.5 人日 | **540** |

## 9. 上线与灰度

### 9.1 阶段

| 阶段 | 范围 | 观察期 | 通过条件 | 止损线 |
|---|---|---|---|---|
| 本地自测 | 无头浏览器 + 逻辑断言 | — | 19 项全绿、3 张截图通过视觉评审 | 任一断言失败 |
| Dogfood | 作者本人多设备 | 1 天 | 无阻断性缺陷 | 出现无法重开的死锁 |
| Canary | 仅通过直接链接访问 | 2 天 | 无运行期报错 | 首屏 > 2s |
| GA | GitHub Pages 主域 | — | — | — |

> 静态站点没有服务端灰度能力，Canary 通过"不公开链接 + 版本化路径"实现，属于弱灰度，**这是本方案已知的局限**。

### 9.2 回滚

- **方式**：`git revert` 后等待 Pages 重建。
- **耗时**：约 **40–60 秒**（含 Pages 构建），实测构建约 20s + CDN 生效。
- **可逆性**：高——无后端、无数据迁移、无用户状态变更（localStorage 仅最高分，格式向前兼容）。

### 9.3 沟通

`README.md` 维护变更记录；不以破坏性方式修改 `localStorage` 键名。

## 10. 风险与依赖

| 风险 | 概率 | 影响 | 缓解措施 | 触发后动作 |
|---|---|---|---|---|
| 静态资源 CDN 不可达 | 中（实测 33% 失败） | 高（裂图/白屏） | 图片改 jsDelivr；页面资源全部同源 | 换 CDN 或改自托管 |
| 滑动与页面滚动冲突 | 中 | 高（移动端不可玩） | `touch-action: none` | 立即回滚手势实现 |
| 高 DPI 移动端掉帧 | 中 | 中 | DPR 上限 2；粒子数量按 reduced-motion 削减 | 降 DPR 上限至 1.5 |
| 浏览器自动播放策略拦截音效 | 高 | 低 | 首次用户手势后初始化 AudioContext | 静默失败，不阻塞游戏 |
| 输入缓冲带来"延迟感" | 低 | 中 | 深度固定为 2，并在 `turn_ignored` 埋点观测 | 降为 1 并 A/B |
| Pages 构建未生效 | 低 | 中 | 部署后立即抓取线上首页验证 | 重新触发构建 |

**外部依赖**：GitHub Pages（托管）、jsDelivr（仅 README 截图）、Web Audio API、Canvas 2D、localStorage。**无后端、无第三方脚本、无包管理依赖。**

### B. 决策日志（ADR）

| 编号 | 决策 | 备选 | 理由 |
|---|---|---|---|
| ADR-1 | 渲染用 Canvas 2D | DOM、WebGL | 576 格逐帧更新，DOM 必掉帧；WebGL 无收益 |
| ADR-2 | 输入缓冲深度 2 | 0 / 1 / 3 | 3 有延迟感，0/1 会丢键 |
| ADR-3 | 截图改走 jsDelivr | 相对路径（→ raw） | raw 实测 67% 成功率，门面不可赌 |
| ADR-4 | 开局遮罩改为**底部渐变** | 统一半透明遮罩 | 截图评审发现"棋盘像空盒子"，第一印象失真 |
| ADR-5 | 修掉"点按开局触发两次启动" | 保留双监听 | stage 与 overlay 监听叠加导致 `start()` 执行两次 |
| ADR-6 | 合成音效而非音频文件 | mp3 资源包 | 省 1–2 个请求与授权成本；可静音 |

### C. 未验证假设与验证方式

| 假设 | 验证方式 | 预计成本 |
|---|---|---|
| 首屏 > 2s 显著提升跳出 | 构造人为延迟版本做 A/B，观测 5s 内跳出率 | 2 人日 |
| 单局 45–120s 最优 | 接入 `game_over.duration_ms` 分布 | 1 人日 |
| 缓冲深度 2 优于 1 | `turn_ignored` 埋点 + 误触率对比 | 1 人日 |

### D. 术语表

| 术语 | 定义 |
|---|---|
| 输入缓冲 | 暂存待执行转向的队列，避免快速连打丢键 |
| 帧插值 | 在两次逻辑步进之间按比例插值绘制位置 |
| 步进（step） | 蛇前进一格的逻辑单位；速度以"格/秒"表示 |
| 护栏指标 | 不能被牺牲的底线指标（帧率、误触率、错误数） |
| 反指标 | 为达成目标指标而可能被牺牲的指标 |
